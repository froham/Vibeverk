# Compliance Documentation

This folder contains templates and checklists for GDPR and privacy compliance work on Vibeverk customer deployments.

**Important:** All templates in this folder are starting points that require customer-specific confirmation and qualified legal review before use. They are not legal approval and do not constitute legal advice. Each template must be completed with actual customer-specific facts before it can be used for compliance purposes.

| File | Description |
|---|---|
| [data-map-template.md](data-map-template.md) | Reusable template for mapping data flows per customer deployment |
| [customer-go-live-checklist.md](customer-go-live-checklist.md) | GDPR/compliance checklist to complete before a customer site goes live |
| [data-map-vibeverk.md](data-map-vibeverk.md) | First real, code-grounded data map for the `vibeverk.no` production tenant (2026-07-16 Privacy Advisor pass) — a filled instance of the template above, not a replacement for it |
| [data-map-sunnvask-notes.md](data-map-sunnvask-notes.md) | What differs / is still open for the Sunnvask showcase tenant, relative to `data-map-vibeverk.md` |
| [draft-privacy-policy-thirdparty-section.md](draft-privacy-policy-thirdparty-section.md) | Draft third-party/processor section for `vibeverk.no`'s own privacy policy (2026-07-16, updated 2026-07-18 for inbound email) — not approved for use, needs legal sanity-check |
| [draft-inbound-email-legal-basis-memo.md](draft-inbound-email-legal-basis-memo.md) | Draft memo (2026-07-18) on the open legal-basis question for automatic CRM profile creation from unrecognized inbound email senders — not legal advice, prepares the question for qualified legal review |
| [legal-complexity-vs-value-2026-08-06.md](legal-complexity-vs-value-2026-08-06.md) | 2026-08-06 decision-support document: for each open legal question found while planning the Console privacy-policy system overhaul, weighs legal complexity against actual product value — recommends which items to build proper support for vs. simplify/remove rather than engineer around.
