**External Codex third-party review of the 0.32.0 restore path (item 3) — BLOCKER, actioned same day.** Verified directly against the code (not taken on faith): `restoreTable()`'s delete-then-insert has no transaction, and the "one table at a time" isolation the code's own comment claimed doesn't actually hold because of FK actions on sibling tables (`crm_customers.bedrift_id` → `crm_bedrifter` is `ON DELETE SET NULL`, `crm_comms.customer_id` → `crm_customers` is `ON DELETE CASCADE`) — a mid-restore failure can cause cross-table, irreversible data loss.
